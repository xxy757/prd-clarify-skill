## 1. 背景与要解决的问题

主管经常漏看请假申请，员工要私下催。

## 2. 目标与成功标准

让主管快速、及时地处理请假、调休等。

## 3. 范围

### 3.1 本次要做

1. 提交请假后提醒直属主管。

### 3.2 本次不做


## 4. 使用者与入口

| 角色 | 在哪里用 | 做什么 | 量级 |
|---|---|---|---|
| 主管 | 企业聊天工具 | 收提醒 | 50 人 |

## 5. 主流程

1. 员工提交请假 → 系统发提醒给直属主管 → 主管看到消息。

## 7. 边界情况

| 编号 | 情况 | 系统应该怎么做 |
|---|---|---|
| D1 | 没有数据时 | 不适用：提醒由提交触发 |
| D2 | 数据很多时 | 不适用：一次只有一条 |
| D3 | 重复操作 | 同一申请只提醒一次 |
| D4 | 撤回与修改 | 撤回后再发一条撤回通知 |
| D5 | 人员调岗 / 离职 / 换领导 | |
| D6 | 多人同时操作 | 不适用：只有一个审批人 |
| D7 | 失败、超时、无人处理 | 24 小时未处理再提醒一次 |

## 11. 验收标准

| 编号 | 验收标准 | 对应规则/边界 |
|---|---|---|
| AC1 | 主管能收到提醒 | |
| AC2 | 当同一申请被重复提交时，系统应只提醒一次。 | D3 |
| AC3 | 当员工撤回申请时，系统应通知主管已撤回。 | D4 |
| AC4 | 当提交后员工调岗时，系统应仍提醒原主管。 | D5 |
| AC5 | 当主管 24 小时未处理时，系统应再提醒一次。 | D7 |
| AC6 | 当上线前已有未审批申请时，系统应不发提醒。 | D8 |

## 12. 上线方式
